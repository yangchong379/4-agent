# 04 AI辅助与实际个人贡献

我提供了第 4 题需求和独立仓库，确认将它纳入联合真实评估，并在本机完成接口密钥输入。我要求逐条整理输入、输出、工具检查与处理过程，并推动修复脚本验收漏检主题一致性的问题。AI 协助完成需求拆解、源码、合成素材、模型接入、测试、文档和 GitHub 交付，个人独立编码工时未单独记录。

复用题2的通用HTTPS模型调用适配器、拒绝批量调用与纠正、调用ID回传、脱敏及本机窗口；独立替换工具schema和提示。旁白来源校验、逐镜估时、脚本版本与检查失效机制为本题新实现。无框架、多Agent或跨项目运行依赖。

## 我的设计思路与复盘

**先把好脚本拆成可检查的条件。** 我把原主题、事实来源和时长分别看待。分镜可以根据受众和风格调整，但旁白里的产品能力要能回到素材原文。字幕主题下，即使某条贴纸事实有来源，也不能作为满足该主题的依据。

**把检查反馈用于修改。** 我理解的处理顺序是先检索，再写分镜，再按同一个版本检查事实和时长。30 秒的离线用例里，首稿估算为 36.5 秒。压缩停留时间后，新稿为 27.5 秒，需要重新估时和检查规则。若素材不足，可以改写查询补查或返回缺口。当前估时是模拟值，验收使用时长上限。

**从漏检补回业务条件。** 我要求逐条说明实际输入、输出和检查过程。AI 复核真实结果时发现，一条字幕主题请求用了贴纸事实，却被标为完成。我要求修复主题一致性漏检。AI 加入原主题核验后做了离线回归，有字幕素材时补查并引用 P02，只有贴纸资料时返回缺素材。我的贡献是提出逐条复盘和修复要求，代码、检查逻辑与离线回归由 AI 协助完成。见[时长修改记录](../examples/runs/mock/duration_revision/result.json)、[真实评估复核](../examples/runs/live-20261105-014727-396675/REVIEW.md)和[主题一致性回归](../examples/regressions/topic-consistency.json)。

## 真实评估、业务复核与修复

AI 启动联合评估并复核原始 Trace。本题修复前真实模型的 12 组自动断言均通过，复核发现一例把有来源的贴纸事实用在字幕主题上并判为完成。我要求修复后，AI 增加了原主题核验并执行离线回归。回归中，有字幕资料时补查并引用 P02，仅有贴纸资料时返回 `needs_materials`。原始真实记录与修复后离线结果分别保留。见[真实模型复核](../examples/runs/live-20261105-014727-396675/REVIEW.md)和[主题一致性回归](../examples/regressions/topic-consistency.json)。
